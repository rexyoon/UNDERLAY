# 상시 프롬프트

> 원본: `docs/UNDERLAY.pdf` 23장. Phase와 상관없이 매일 쓰는 프롬프트들이다. 짧은 말로 불러도 CLAUDE.md가 같은 행동을 하게 되어 있지만, 처음 몇 번은 전문을 쓰는 편이 결과가 안정적이다.

## 세션 시작

```text
세션 시작. CLAUDE.md → docs/PROGRESS.md → 현재 Phase 프롬프트 순서로 읽어라.
지난 세션 상태를 3줄로 요약하고, 타이핑 중이던 파일이 있으면 그것부터 이어 가자고 제안해라.
없으면 오늘 할 일 후보 3개를 예상 소요와 함께 제시하고, 오늘 끝나면 바탕화면에서 무엇이 보일지 한 줄로 알려 준 뒤 멈춰라.
```

## 다음 파일 — 타이핑 모드

```text
다음으로 내가 칠 C++ 파일을 보여 줘. 형식:
[순번/전체] 경로 · 예상 줄 수 (짝 파일 안내) → 왜 필요한가(2~3줄) → 전체 코드(줄 번호 없이, #include 포함)
→ 타이핑하며 볼 곳 3개 → "다 치면 '작성 완료'라고 말해줘"
이 파일에 처음 나오는 C++ 문법이 있으면 Java·Kotlin이라면 어떻게 썼을지 한 줄씩 덧붙이고,
포인터·참조가 있으면 각 객체의 주인이 누구인지 적어라.
```

## 작성 완료 — 대조 검사

```text
작성 완료. 방금 친 파일을 읽고, 네가 보여 준 코드와 대조해라.
1) 다른 곳을 줄 번호와 함께 표로 (오타 / 빠진 줄 / 의도된 변형으로 보이는 것)
2) 고치지 말고, 의도된 변형인지 물어봐라
3) 차이가 없거나 내가 확인하면 빌드하고 관련 테스트를 돌려라
4) 통과하면 docs/TYPING_LOG.md에 한 줄(배운 C++ 개념 포함) 추가하고 다음 단계를 제안해라
```

## 빌드 오류 같이 보자

```text
빌드(또는 링크) 오류가 났다. 출력 전체를 읽고:
1) 첫 번째 진짜 오류가 무엇인지 (뒤따르는 연쇄 오류와 구분)
2) 한국어로 무슨 뜻인지, C++에서 왜 이런 오류가 나는지 (컴파일 오류인지 링크 오류인지도)
3) 어느 파일 몇 번째 줄을 어떻게 고치면 되는지
고치지는 말고 알려만 줘라. 내가 고친 뒤 "다시 빌드"라고 하면 빌드해라.
```

## 설명해줘 — 학습 모드

```text
방금 만든 코드를 설명해줘.
1) 실행 흐름 순서대로 거치는 함수·클래스 (파일:줄 번호), 어느 스레드에서 도는지
2) 이 코드가 가진 자원(핸들, COM, 메모리)과 각각 언제 해제되는지
3) 이 부분을 면접에서 설명한다면 쓸 세 문장
4) 내가 직접 바꿔볼 만한 작은 실습 하나 — 정답은 말하지 말 것
```

## 범위 차단

```text
방금 나온 제안(또는 내가 말한 아이디어)이 현재 Phase 범위 안인지 판단해라.
범위 밖이면 구현하지 말고 docs/PROGRESS.md 백로그에 "날짜 · 아이디어 · 관련 Phase · 미루는 이유" 한 줄로
적은 뒤, 원래 하던 작업으로 돌아가라.
```

## 바탕화면이 이상할 때

```text
바탕화면 증상: [안 보임 / 아이콘 위에 그려짐 / 위치가 어긋남 / 종료 후 잔상 / 탐색기 재시작 후 사라짐]
바로 고치지 마라.
1) 로그에서 감지된 구조(CLASSIC/RAISED)와 창 트리를 찾아 요약
2) 원인 가설 3개를 가능성 순으로, 각각 확인 방법
3) 가장 싸게 확인할 수 있는 것부터 진행. 수정이 필요하면 기존 파일은 diff로, 새 파일은 타이핑 형식으로 제시하고 멈춰라.
```

## 코드 리뷰 · ADR · Phase 완료 · 세션 종료

```text
[코드 리뷰] 이번 Phase에서 바뀐 코드를 리뷰해라. 관점:
 (1) 자원 누수(RAII 빠진 곳) (2) 스레드 규칙 위반(렌더 외 스레드의 D3D 접근, 공유 변수)
 (3) 순수 로직에 Windows 헤더 유입 (4) 예외가 스레드·콜백 경계를 넘는 곳 (5) 테스트가 비어 있는 곳
 심각도(높음/중간/낮음) · 위치 · 문제 · 제안으로 표를 만들어라. 수정은 내 승인 후에.

[ADR] 방금 내린 결정 [주제]를 docs/adr/NNN-제목.md 로 남겨라.
 형식: 맥락 / 선택지(비교표) / 결정 / 결과와 트레이드오프 / 다시 검토할 조건

[Phase 완료] Phase N 완료 보고를 작성해라: 완료 조건 체크표(통과/미통과/근거), 테스트·수동 점검 결과,
 이번 Phase에 내가 친 파일 수와 줄 수(TYPING_LOG 기준), 이번 Phase의 C++ 개념 지도 항목별 "설명할 수 있는지" 확인 질문 3개,
 만든 ADR, 알려진 문제. PROGRESS.md를 갱신하고 커밋 메시지를 제안한 뒤 멈춰라.

[세션 종료] docs/PROGRESS.md를 갱신해라: 완료 / 진행 중(타이핑 중인 파일 포함) / 다음 세션 첫 할 일 / 막힌 것 / 백로그.
 커밋되지 않은 변경이 있으면 목록과 커밋 메시지를 제안해라.
```
