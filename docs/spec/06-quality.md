## 14. 성능 · 안정성

바탕화면은 하루 종일 켜져 있다. 그래서 작은 낭비도 크게 쌓이고, 작은 버그도 "바탕화면이 깨졌다"로 보인다.

| 주제 | 계획 |
|---|---|
| 측정 도구 | 작업 관리자(GPU 엔진 열), PresentMon(프레임 시간), Visual Studio 진단 도구(CPU·메모리), 그래픽 디버거 |
| 장치 손실 | 드라이버 업데이트·GPU 재설정으로 Direct3D 장치가 사라지면 감지해 장치와 스왑체인을 다시 만든다 |
| 절전 · 복귀 | 복귀 후 모니터 구성을 다시 읽고 필요하면 창·스왑체인 재생성 |
| 크래시 | 처리되지 않은 예외 필터 → 덤프 파일 기록 → 바탕화면 복구 시도. 다음 실행 때 "지난번 비정상 종료" 알림 |
| 로그 | spdlog 회전 로그(용량 제한). 바탕화면 붙이기 실패 시 창 트리 전체를 기록 |
| 백신 · SmartScreen | 서명 없는 실행 파일은 SmartScreen 경고가 뜬다. 전역 키보드·마우스 훅을 쓰지 않아 오탐 가능성을 줄인다. 코드 서명은 비용 때문에 백로그 |

## 15. 테스트 전략

시스템 프로그램은 자동 테스트만으로 다 확인할 수 없다. 그래서 두 갈래로 간다. 순수 로직은 GoogleTest로 꼼꼼히, Windows와 맞닿은 부분은 수동 점검표로 매번 같은 순서로.

### 자동 테스트 (GoogleTest)

| 대상 | 무엇을 확인하나 |
|---|---|
| FFT | 무작위 신호에서 직접 만든 FFT와 느린 DFT 결과가 오차 범위 안에서 같다. 1kHz 사인파의 봉우리가 맞는 칸에 선다 |
| 대역 계산 | 경계 공식, 저음 대역의 최소 한 칸 보장, 무음이면 전부 0 |
| 다듬기 | 오를 때 빠르고 내릴 때 느리다 |
| 3중 버퍼 | 두 스레드로 수백만 번 돌려도 찢어진 값(쓰다 만 값)을 읽지 않는다 |
| 멈춤 판단 | 조건 조합 표 전체 (우선순위 포함) |
| 디바운스 | 300ms 안의 깜빡임은 무시 |
| 바탕화면 구조 감지 | 가짜 창 트리(CLASSIC, RAISED, 이상한 트리)로 판정 결과 확인 |
| 채우기 계산 | 10장의 울트라와이드 예시 숫자 그대로 |
| 패키지 검증 · 플레이리스트 | 정상·비정상 project.json, 고정 시드 셔플 순서 |
| 라이브러리 DB | 메모리 SQLite로 마이그레이션·조회 |
| 문자열 변환 | UTF-8 ↔ UTF-16 왕복 (한글·이모지 포함) |

### 수동 점검표 — Phase가 끝날 때마다 해당 줄만

| 환경 · 상황 | 확인할 것 |
|---|---|
| Windows 11 24H2 이후 (RAISED) · 23H2 이전 또는 Windows 10 (CLASSIC, 가상 머신 가능) | 아이콘 뒤에 보이는지, 아이콘 클릭·드래그가 되는지 |
| 모니터 2대 (주 모니터 왼쪽에 보조 모니터 포함) | 위치·크기, 모니터별 배경 |
| 배율 100% · 150% · 175% | 흐릿하지 않은지, 크기 맞는지 |
| 탐색기 재시작 · 모니터 뽑기/꽂기 · 절전 복귀 · 잠금 해제 | 5초 안에 자동 복구 |
| 전체화면 게임 · 테두리 없는 창 게임 · 전체화면 영상 · Alt+Tab | 멈추고 다시 켜지는지, 깜빡임 없는지 |
| 강제 종료 · 크래시 테스트 메뉴 | 바탕화면 잔상 없음 |
