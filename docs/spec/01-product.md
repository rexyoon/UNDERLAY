## 02. UNDERLAY는 무엇인가

UNDERLAY는 바탕화면 아이콘 아래에서 움직이는 배경을 그리는 Windows 앱이다. 영상, 셰이더, 웹 페이지를 배경으로 띄우고, 지금 PC에서 나오는 음악에 맞춰 반응하게 만든다. 게임이나 전체화면 영상을 켜면 스스로 멈춰 GPU를 돌려준다.

### 왜 이걸 만드나

| 목적 | 이 프로젝트가 주는 것 |
|---|---|
| 시간 때우기 | Phase마다 눈에 보이는 결과가 나온다. 아이콘 뒤에 색이 깔리는 순간, 영상이 돌기 시작하는 순간, 음악에 맞춰 원이 출렁이는 순간 |
| C++ 익히기 | Win32 메시지 루프, COM, Direct3D, 스레드, lock-free 버퍼, FFT까지 — C++가 아니면 하기 어려운 일들로 자연스럽게 배운다 |
| 포트폴리오 | 웹·백엔드 위주 포트폴리오에 "시스템·그래픽스·오디오"라는 다른 축이 생긴다 |

### 이미 있는 것들, 그리고 UNDERLAY의 자리

라이브 월페이퍼 앱은 이미 있다. 유료로 유명한 앱도 있고, 무료 오픈소스 앱도 있다. Windows 11도 영상 배경화면 기능을 시험 중이다(정식 기능은 아니다). UNDERLAY는 이들과 경쟁하려는 게 아니라, 그 엔진을 직접 만들어 보는 것이 목표다. 그래도 내 앱만의 특징은 세 가지로 잡는다.

1. **음악에 반응하는 셰이더** — 시스템 소리를 직접 분석(FFT)해 셰이더에 넘긴다. 지난번에 이야기한 "원형 음파"가 첫 번째 배경이 된다.
2. **왜 멈췄는지 보여 주는 앱** — "게임 실행 중이라 2번 모니터 정지" 같은 이유를 트레이와 설정 화면에 그대로 보여 준다. 멈춤 규칙을 내가 이해하고 고칠 수 있다.
3. **셰이더 핫 리로드** — 셰이더 파일을 저장하는 순간 바탕화면이 바뀐다. 배경을 만드는 과정 자체가 놀이가 된다.

### 하지 않는 것

| 하지 않는 것 | 이유 |
|---|---|
| macOS · Linux 지원 | 바탕화면 구조가 완전히 다르다. Windows에서 끝까지 가는 쪽이 배우는 게 많다 |
| 다른 앱의 배경 파일 형식 지원, 창작마당 연동 | 남의 형식·서비스에 기대지 않는다. 내 패키지 형식을 쓴다 |
| 판매 · 결제 | 취미 프로젝트. 대신 GitHub에 공개하고 설치 파일을 배포한다 |
| 3D 장면 편집기 | 범위가 끝없이 커진다. 셰이더와 웹으로 충분히 표현할 수 있다 |

### 이름

UNDERLAY는 "아래에 까는 층"이라는 뜻이다. 오버레이(overlay)가 화면 위에 덮는 것이라면, 이 앱은 아이콘 아래에 깐다. 대안은 BACKDROP, STRATA다. 공개 전에는 같은 이름의 앱이 있는지 확인하고, 기존 유명 앱의 이름·로고·화면 구성을 흉내 내지 않는다.

## 03. 배경 종류와 패키지

배경은 네 종류다. 무겁기도, 배우는 것도 다르다. 모두 같은 인터페이스(`IWallpaper`) 뒤에 숨겨서, 엔진은 지금 어떤 종류를 그리는지 몰라도 되게 만든다.

| 종류 | 무엇 | 그리는 방법 | 무게 | C++로 배우는 것 | Phase |
|---|---|---|---|---|---|
| 셰이더 | 수식으로 그리는 움직이는 그림 (원형 음파, 오로라, 노이즈) | Direct3D 11 + HLSL 픽셀 셰이더 | 가벼움 | GPU 파이프라인, 상수 버퍼, 파일 감시 | 3 |
| 영상 | mp4 반복 재생 | Media Foundation(하드웨어 디코딩) → D3D11 텍스처 | 중간 | COM, 비동기 콜백, 텍스처 복사 | 4 |
| 이미지 | 정지 이미지, 슬라이드쇼 | D3D11 텍스처 | 아주 가벼움 | 이미지 로딩(WIC) | 4 |
| 웹 | HTML·JS로 만든 배경 (시계, 날씨, 웹 비주얼라이저) | WebView2 | 무거움 (브라우저 엔진) | 다른 프로세스와의 메시지, JSON | 7 |

### 패키지 형식 — 폴더 하나 = 배경 하나

```
wallpapers/
└── ring-visualizer/
    ├── project.json   ← 이 배경의 정의
    ├── main.hlsl      ← 셰이더 배경이면 셰이더, 영상이면 mp4, 웹이면 index.html
    └── preview.jpg    ← 라이브러리 썸네일
```

```json
{
  "format": 1,
  "type": "shader",
  "title": "Ring Visualizer",
  "entry": "main.hlsl",
  "preview": "preview.jpg",
  "audioReactive": true,
  "properties": {
    "ringColor": { "type": "color", "default": "#2fd9c6" },
    "sensitivity": { "type": "slider", "min": 0.2, "max": 3.0, "default": 1.0 }
  }
}
```

### 설계 원칙

`properties`는 배경이 스스로 선언한 조절값이다. 설정 화면은 이 선언을 읽어 슬라이더·색상 선택기를 자동으로 만든다. 셰이더면 상수 버퍼로, 웹이면 JS 이벤트로 값이 전달된다. 새 배경을 추가할 때 C++ 코드는 한 줄도 바뀌지 않는다.

### 샘플 배경의 저작권

샘플 배경은 직접 만들거나 이용 조건을 확인한 것만 넣는다. 영상은 직접 찍었거나 상업·재배포가 허용된 것만, 셰이더는 직접 쓴 것만 넣는다. 인터넷에 공개된 셰이더 상당수는 비상업·동일조건 라이선스라 앱에 그대로 묶어 배포하면 안 된다.

## 04. 핵심 기능

기능 목록이다. 각 기능에 Phase 번호(16장 로드맵)를 붙였다. 위쪽일수록 먼저 만든다.

| # · Phase | 기능 | 내용 |
|---|---|---|
| 01 · PHASE 1 | 아이콘 아래에 그리기 | 바탕화면 아이콘은 그대로 두고 그 밑, 기본 배경 위에 내 창을 끼운다. Windows 10식 구조와 11 24H2 이후 구조를 감지해 각각 다르게 붙인다. 탐색기가 재시작돼도 다시 붙고, 종료하면 원래 배경으로 돌아간다. |
| 02 · PHASE 2 | 모니터마다 다른 배경 | 모니터마다 창과 그리기 버퍼를 따로 둔다. 모니터를 꽂거나 빼면 자동으로 다시 배치하고, 모니터마다 다른 배율(DPI)도 맞춘다. |
| 03 · PHASE 3 | 셰이더 배경 + 핫 리로드 | HLSL 파일 하나로 배경을 만든다. 시간·해상도·마우스·음악 값을 받는다. 파일을 저장하면 바로 다시 컴파일해 바탕화면에 반영하고, 오류가 나면 이전 화면을 유지한 채 오류를 보여 준다. |
| 04 · PHASE 4 | 영상 · 이미지 배경 | mp4를 하드웨어 디코딩으로 반복 재생한다. 화면 채우기 방식(꽉 채우기·맞추기·늘리기)을 고른다. 배경 영상의 소리는 끈다. |
| 05 · PHASE 5 | 스스로 멈추기 | 전체화면 게임, 창이 화면을 다 가릴 때, 배터리, 화면 잠금, 원격 데스크톱에서 멈춘다. 모니터 단위로 판단하고, 멈춘 이유를 보여 준다. 멈춘 동안은 그리기를 완전히 쉰다. |
| 06 · PHASE 6 | 음악에 반응 | 스피커로 나가는 소리를 가로채(루프백) 64개 주파수 대역으로 나누고, 부드럽게 다듬어 셰이더에 넘긴다. 첫 작품은 원형 음파. |
| 07 · PHASE 7 | 웹 배경 | HTML·JS로 만든 배경을 띄운다. 웹 배경에도 음악 대역 값과 조절값을 JS 이벤트로 넘겨, 웹 기술로도 음악 반응 배경을 만들 수 있게 한다. |
| 08 · PHASE 8 | 라이브러리 · 설정 · 트레이 | 배경 폴더를 훑어 라이브러리를 만들고, 썸네일 격자에서 모니터별로 지정한다. 조절값 자동 UI, 플레이리스트(일정 간격 교체), Windows 시작 시 자동 실행, 트레이 메뉴. |

## 05. 화면 구조

이 앱의 진짜 화면은 바탕화면 자체다. 따로 보는 화면은 셋뿐이다. 트레이 메뉴(평소), 설정 창(배경 고르기·조절), 디버그 오버레이(개발 중 성능 확인).

PDF의 화면 시안 네 장을 글로 옮긴다. (숫자는 화면 설명을 위한 가상의 예시값이다.)

### TRAY / 우클릭 메뉴

위에서 아래로 다음 항목이 놓인다.

1. `UNDERLAY · 재생 중 1/2 모니터` (상태 줄)
2. `2번 모니터 정지` / `전체화면 앱 실행 중 (game.exe)` (멈춘 이유 표시)
3. `다음 배경`
4. `모두 일시정지 / 다시 재생`
5. `설정 열기`
6. `종료 (원래 배경으로 복구)`

### SETTINGS / 라이브러리 (Dear ImGui)

- 왼쪽 세로 탭: 라이브러리 · 모니터 · 멈춤 규칙 · 오디오 · 성능 · 일반
- 가운데 썸네일 격자: `ring` (Ring Visualizer · 셰이더), `aurora` (Aurora · 셰이더), `rain.mp4` (Night Rain · 영상), `clock` (Minimal Clock · 웹), `photo` (Mountain · 이미지), `+ 폴더 추가`
- 오른쪽 상세 패널(선택한 Ring Visualizer): 태그 `셰이더` `음악 반응`, 조절값 `ringColor ■ #2fd9c6`, `sensitivity` 슬라이더 `━━━●━━ 1.0`, 버튼 `1번 모니터에 적용`, `2번 · 모두에 적용`

### SETTINGS / 모니터

- 모니터 배치도에 모니터 두 개가 그려진다.
  - `1 · 2560×1440 · 150%` — Ring Visualizer, 재생 60fps
  - `2 · 1920×1080` — Night Rain, 정지 · 전체화면
- 설명: 모니터를 누르면 그 모니터의 배경·채우기 방식·FPS 상한을 고른다.

### SETTINGS / 오디오 · 성능

- 입력: 기본 출력 장치(루프백) · 신호 −18 dB
- 모니터 1 60 fps · 프레임 3.1 ms / 모니터 2 정지
- 메모리 112 MB / 디코딩 하드웨어

설정 창은 Dear ImGui로 그리는 보통 창이고, 닫으면 렌더링에서 완전히 빠진다.

### 디버그 오버레이

개발 중에는 단축키로 바탕화면 구석에 한 줄짜리 상태를 띄운다. `MON1 60fps 3.1ms · audio −18dB · policy RUN · layout RAISED`. 바탕화면 구조를 어떤 방식으로 감지했는지(`CLASSIC` / `RAISED`)까지 보여 주면 버그 리포트가 쉬워진다.

## 06. 성공 지표

손님이 없는 앱이므로 지표는 두 종류다. "똑똑하게 가벼운가"를 숫자로 확인하는 성능 지표, 그리고 "C++를 얼마나 익혔나"를 확인하는 학습 지표.

### 성능 지표 — 목표값

| 지표 | 목표 | 측정 방법 |
|---|---|---|
| 일시정지 중 자원 | GPU 사용 ≈ 0%, CPU 0.5% 이하 | 작업 관리자 GPU 엔진 열, 성능 패널 |
| 셰이더 배경 | 60fps에서 프레임 시간 흔들림 없음 | PresentMon, 내장 성능 패널 |
| 1080p 영상 배경 | CPU 5% 이하 (하드웨어 디코딩) | 내 PC에서 측정한 값을 README에 기록 |
| 메모리 | 웹 배경 없이 150MB 이하 | 작업 관리자 (WebView2는 따로 측정) |
| 음악 → 화면 지연 | 50ms 이하 | 메트로놈 영상 + 슬로 모션 촬영으로 확인 |
| 종료 · 크래시 후 | 바탕화면에 잔상 0 | 강제 종료 테스트 |
| 탐색기 재시작 후 | 5초 안에 자동 복구 | 작업 관리자에서 탐색기 재시작 |
| 시작 시간 | 로그인 후 1초 안에 첫 프레임 | 로그 타임스탬프 |

### 학습 지표

| 지표 | 확인 방법 |
|---|---|
| 직접 친 C++ 파일 수 · 줄 수 | docs/TYPING_LOG.md |
| Phase별 C++ 개념 체크리스트 통과 | 16장 개념 지도 — Phase 완료 때 "내 말로 설명" |
| 혼자 고친 빌드 오류 · 크래시 수 | TYPING_LOG의 "배운 것" 칸 |
| 내가 매일 이 배경을 켜 두는가 | 결국 이게 제일 중요한 지표 |
