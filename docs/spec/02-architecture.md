## 07. 기술 스택과 투트랙 결정

C++20과 Windows가 직접 제공하는 API를 중심에 둔다. 외부 라이브러리는 UI·저장·로그·테스트처럼 "배우려는 대상이 아닌 것"에만 쓴다. FFT처럼 배우고 싶은 것은 직접 만든다.

### 확정 스택

| 영역 | 선택 | 이유 |
|---|---|---|
| 언어 · 컴파일러 | C++20, MSVC (Visual Studio 2026) | 학습 목적. Windows API와 가장 가깝고 디버거·그래픽 디버거가 강력하다 |
| 빌드 · 의존성 | CMake + vcpkg (매니페스트 모드) | Claude Code가 관리한다. 다른 PC에서도 같은 빌드 |
| 창 · 시스템 | Win32 API | 메시지 루프, 트레이, 전원·세션 알림, 바탕화면 붙이기 |
| 그래픽 | Direct3D 11 + DXGI, HLSL (실행 중 컴파일) | 자료가 많고 영상 디코딩과 연결이 쉽다 |
| 영상 · 이미지 | Media Foundation (Media Engine), WIC | Windows 내장, 하드웨어 디코딩 |
| 오디오 | WASAPI 루프백 | 스피커로 나가는 소리를 그대로 받는다 |
| FFT | 직접 구현 (radix-2) | 배우는 대상. 테스트는 느린 DFT 결과와 비교 |
| 웹 배경 | WebView2 (Evergreen 런타임) | Windows 11에 기본 포함 |
| 설정 UI | Dear ImGui (Win32 + DX11 백엔드) | UI도 C++로 익힌다 |
| 저장 | SQLite + nlohmann/json | 라이브러리·설정 / 배경 패키지 |
| 로그 · COM | spdlog · `Microsoft::WRL::ComPtr` | 파일 로그 · Direct3D 예제의 표준 COM 포인터 |
| 테스트 | GoogleTest | 순수 로직 단위 테스트 |
| 배포 | zip + Inno Setup 설치 파일, GitHub Actions(Windows 러너) | Phase 9 |

### 투트랙 A — 렌더링: 전부 WebView2 vs 직접 렌더링 + 웹만 WebView2

| 기준 | 전부 WebView2 | Direct3D 11 + 웹만 WebView2 (기본값) |
|---|---|---|
| 메모리 | 모니터마다 브라우저 엔진 → 무겁다 | 셰이더·영상은 가볍다 |
| 멈추기 | 페이지 스크립트가 협조해야 한다 | 그리기 루프를 내가 멈추면 끝 |
| C++로 배우는 것 | 창 관리 정도 | Direct3D, Media Foundation, COM까지 |
| 개발 속도 | 빠르다 | 느리다 |

**결정** — 직접 렌더링 + 웹만 WebView2. 이 프로젝트의 목적이 C++ 학습이고, "멈출 땐 확실히 멈춘다"가 핵심 특징이다. 웹 배경은 웹으로만 할 수 있는 것(웹 비주얼라이저, 시계·날씨 위젯)에만 쓴다.

### 투트랙 B — 설정 UI

| 기준 | Dear ImGui (기본값) | WebView2 웹 UI | WinUI 3 |
|---|---|---|---|
| 언어 | C++ (내가 친다) | HTML·JS(Claude Code) + C++ 메시지 다리 | C++/WinRT + XAML |
| 모양 | 개발 도구 느낌, 꾸밀수록 손이 많이 감 | 자유롭게 예쁘게 | Windows 기본 앱 모양 |
| 난이도 | 낮음 | 중간 | 높음 (설정·빌드가 복잡) |
| 의존성 | 아주 작음 | WebView2 | Windows App SDK |

**결정** — Dear ImGui. 같은 Direct3D 장치 위에서 돌고, "매 프레임 UI를 다시 그린다"는 즉시 모드 개념이 단순하다. 다 만들고 나서 예쁘게 바꾸고 싶어지면 웹 UI로 갈아타는 것을 백로그에 둔다.

### 투트랙 C · D · E — 빌드, 자원 관리, 오류 처리

| 결정 | 기본값 | 대안 | 이유 |
|---|---|---|---|
| 빌드 | CMake + vcpkg | Visual Studio 솔루션 + NuGet | 업계 표준이고, 빌드 파일은 Claude Code가 쓰므로 진입 장벽이 낮다 |
| Win32 자원 관리 | 직접 만든 RAII 래퍼 (`unique_ptr` + 사용자 삭제자) | Microsoft WIL 라이브러리 | HANDLE·HWND·HICON을 직접 감싸 보며 RAII를 몸으로 익힌다. 익숙해지면 WIL을 검토 |
| 오류 처리 | HRESULT 확인 → 실패 시 예외 (`ThrowIfFailed`), 스레드 경계에서 잡아 로그 | 전부 오류 코드 반환 | Direct3D 예제들의 관례. 실패 지점을 놓치지 않는다 |
| 테스트 | GoogleTest | Catch2 | 가장 널리 쓰인다. vcpkg로 바로 붙는다 |

## 08. 시스템 아키텍처

스레드는 셋이다. 메인(창·트레이·이벤트·UI), 렌더(Direct3D), 오디오(캡처·분석). 셋은 서로를 기다리지 않는다. 오디오가 끊겨도 화면은 돌고, 렌더가 느려도 소리 분석은 계속된다.

### 구조 그림 (글로 풀어 씀)

PDF의 그림은 세 개의 스레드 상자와, 오른쪽의 외부 대상(바탕화면·WebView2·디스크), 그리고 스레드 간 규칙 상자로 되어 있다.

**메인 스레드 — Win32 메시지 루프**
- `app` · 트레이 · 단일 인스턴스 — 명령을 렌더 스레드 큐로 보낸다
- `desktop` · 바탕화면에 붙이기 — 구조 감지 · 탐색기 재시작 · 종료 복구 *(청록: 가장 까다로운 곳, 09장)*
- `monitor` · 모니터별 창 — DPI · 꽂기/빼기 감지
- `policy` · 멈춤 조건 수집 + 판단 — 전체화면 · 가림 · 전원 · 잠금 이벤트 *(청록, 12장)*
- `web` · WebView2 호스트 — UI 스레드에서만 만들 수 있다
- `library` · 패키지 · SQLite — 플레이리스트 · 설정
- `ui` · 설정 창 (Dear ImGui) — 열려 있을 때만 그린다
- 메모: 모든 Win32 이벤트 훅과 WebView2는 메시지 루프가 있는 이 스레드에 둔다

**렌더 스레드 — Direct3D 11**
- 명령 큐 처리 — 배경 바꾸기 · 일시정지 · 모니터 변경 · 조절값
- `render` · 장치 1개 + 모니터별 스왑체인 — 프레임 루프 · FPS 상한 · 멈춘 모니터는 건너뜀
- `shader` — HLSL · 상수 버퍼 · 핫 리로드
- `video · image` — Media Engine · WIC
- `IWallpaper — update(dt) · draw(target)`
- 메모: 렌더 스레드만 Direct3D 컨텍스트를 만진다 (장치 컨텍스트는 스레드 안전하지 않다)

**오디오 스레드 — WASAPI 루프백** *(청록, 11장)*
- 캡처 → 슬라이딩 버퍼 → FFT → 64 대역
- 이벤트 방식 캡처, 512 샘플마다 분석
- 결과는 원자적 스냅샷으로 공개 (렌더는 기다리지 않고 최신 값만 읽는다)

**외부 대상**
- 바탕화면 (탐색기): 위에서부터 아이콘 레이어 → UNDERLAY 모니터 창들 → 기본 배경 레이어 (09장에서 자세히)
- WebView2 프로세스: 웹 배경마다 브라우저 엔진, JS로 음악 값 · 조절값 전달
- 디스크: `wallpapers/` · `library.db` · `logs/`

**스레드 간 규칙**
- 메인 → 렌더: 명령 큐
- 오디오 → 렌더·웹: 최신 스냅샷
- 렌더 → 메인: 상태 보고(FPS 등)
- 공유 변수에 직접 쓰기 금지

청록색은 이 앱에서 가장 까다로운 곳이다: 바탕화면에 붙이기(09장), 멈춤 판단(12장), 오디오 분석(11장).

### 폴더(모듈)와 책임

| 폴더 | 책임 | 스레드 | 운영체제 의존 |
|---|---|---|---|
| `core/` | 로그, 경로, UTF-8 ↔ UTF-16 변환, RAII 래퍼, `ThrowIfFailed` | 공통 | 일부 |
| `app/` | 진입점, 단일 인스턴스, 메시지 루프, 트레이, 명령 분배 | 메인 | 있음 |
| `desktop/` | 바탕화면 구조 감지, 창 붙이기, 탐색기 재시작 대응, 종료·크래시 복구 | 메인 | 있음 |
| `monitor/` | 모니터 목록·DPI·변경 감지, 모니터별 창 | 메인 | 있음 |
| `render/` | Direct3D 장치, 모니터별 스왑체인, 프레임 루프 | 렌더 | 있음 |
| `wallpaper/` | `IWallpaper`, 셰이더·영상·이미지 구현, 웹 호스트 | 렌더 / 메인 | 있음 |
| `audio/` | 루프백 캡처 / **슬라이딩 버퍼·FFT·대역 계산·다듬기** | 오디오 | 캡처만 |
| `policy/` | 멈춤 조건 수집 / **판단 함수** | 메인 | 수집만 |
| `library/` | **패키지 읽기·검증**, SQLite, **플레이리스트 계산** | 메인 | 없음 |
| `ui/` | Dear ImGui 설정 창 | 메인 | 있음 |

> 굵게 표시: 원문에서 굵게 강조한 "순수 로직". PDF 표에서 굵게 표시가 텍스트 추출로 확인되지 않아, 아래 구조 규칙 1번이 열거한 항목(FFT, 대역 계산, 멈춤 판단, 패키지 검증, 플레이리스트)에 맞춰 표시했다.

### RULES · 구조 규칙

1. 굵게 표시한 순수 로직은 Windows 헤더를 include하지 않는다. FFT, 대역 계산, 멈춤 판단, 패키지 검증, 플레이리스트는 입력과 출력만 있는 함수로 만들어 테스트한다.
2. Direct3D 장치 컨텍스트는 렌더 스레드만 만진다. 다른 스레드는 명령 큐에 요청만 넣는다.
3. 스레드 사이에 공유 변수를 직접 쓰지 않는다. 명령 큐(메인 → 렌더)와 3중 버퍼(오디오 → 렌더·웹) 중 하나로만 주고받는다.
4. 문서화되지 않은 동작은 한 곳에 가둔다. 바탕화면 구조를 다루는 코드는 `desktop/` 밖으로 새지 않는다. Windows가 바뀌면 그 폴더만 고친다.
